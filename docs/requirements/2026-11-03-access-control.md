# DSH 权限预设与单次升权审批需求

日期：2026-11-03

状态：实施中。协议、原生 UI、Mock、交互驱动和真机验收按本需求执行。

## 用户目标

把 DSH Host 已有的“权限预设”和“工具越权审批”完整接入原生端。用户需要能：

- 看见当前会话是“仅可查看”“工作区内修改”还是“完全权限”；
- 在需要时切换当前会话权限，并对完全权限作出明确风险确认；
- 当受限工具被沙箱拒绝后，看到 Host 发来的单次升权审批；
- 选择“允许一次”或“拒绝”，并清楚知道允许只影响当前工具调用；
- 区分当前会话权限和新会话默认权限；
- 在断线、超时、请求被撤回或请求已失效时不误放行。

这里的“访问权限控制”不是本机应用锁，也不是多人账户角色管理。应用锁不在
本需求范围内。

## DSH 语义

### 权限预设

Host 的权限预设把沙箱模式和审批策略组合成一个用户选项：

| 预设 | 沙箱行为摘要 | 审批摘要 |
| --- | --- | --- |
| `read-only` | 拒绝文件修改 | 通常通过 `ask` 请求审批 |
| `workspace-write` | 只允许工作区及显式额外根目录写入 | 通常通过 `ask` 请求审批 |
| `danger-full-access` | 绕过文件沙箱 | 默认预设组合使用 `never` |
| `auto` | 实验性自动审查 | 仅当前会话，首期不作为默认 |
| `custom` | 当前组合未匹配到目录项 | 只能展示，不能选中 |

预设的精确沙箱/审批组合由 Host 配置拥有。客户端展示可以简化，但执行语义不能
由客户端自行猜测。

### 单次升权审批

受限调用被拒绝后，工具可以在同一轮次中重试完全相同的调用，并携带：

```text
sandbox_permissions = 足够放行的最窄更宽模式
justification       = 一句人类可读的原因
```

Host 通过 `approval/request` 请求用户决定。审批结果是闭合集合：

```text
allowed-once  仅允许当前这一调用
rejected      用户拒绝
cancelled     请求被撤回
unavailable   没有可用审批通道
```

只有 `allowed-once` 可以放行。单次升权不改变会话的持久权限预设，也不会自动
变成“始终允许”。

### 当前值与默认值

- 当前会话权限来自 Session 的 `permissions` 投影。
- 可选项来自 Host 的进程级权限目录。
- 当前会话切换通过 `/permission <preset>` 写入。
- 新会话默认值来自 `permission.defaultPreset`，只影响之后创建的会话。
- 修改默认值不得改写当前会话，修改当前会话也不得静默改写未来默认值。

## 功能要求

### 当前会话权限

- `PERM-REQ-01` 只有同时取得权威 `permissions` 当前值和权限目录后，才显示
  完整可操作控件。
- `PERM-REQ-02` 当前值未到达前不能伪造“仅可查看”或其他默认标签。
- `PERM-REQ-03` 目录中的选项、名称和说明由 Host 提供；客户端只对
  `read-only`、`workspace-write`、`danger-full-access` 和 `auto` 等已知值
  提供本地化展示别名。
- `PERM-REQ-04` `custom` 可以作为当前状态显示，但不能成为菜单选择目标。
- `PERM-REQ-05` 选择后以 `permissions` 投影确认结果。命令响应成功但投影尚未
  更新时，显示切换中，不把旧值视为新值。
- `PERM-REQ-06` 目录撤回、连接代际变化或当前值冲突时，关闭菜单和确认框，
  回到最近一次权威状态；未知写结果不得自动重试。
- `PERM-REQ-07` 子智能体、只读会话或 Host 未提供权限能力时，不显示一个永远
  失败的入口。

### 完全权限确认

- `PERM-REQ-08` 从权限菜单选择完全权限时，必须先显示风险确认：
  - 标题说明将启用完全权限；
  - 说明会减少确认并允许敏感操作、文件修改和外部命令；
  - 需要用户勾选“我已了解风险”后才启用确认按钮；
  - 取消、关闭和系统 Back 都只关闭确认，不提交。
- `PERM-REQ-09` 通过完整 `/permission danger-full-access` 命令主动提交时，
  视为用户已经明确作出命令级确认；带参命令仍直接执行。
- `PERM-REQ-10` `auto` 是实验性当前会话选项。首期可以显示其当前状态，但不把
  它作为未来默认值，也不在普通新用户路径中主动推荐。

### 单次升权审批

- `PERM-REQ-11` `approval/request` 必须以会话内 interaction 表面展示，不能作为
  普通助手文本或原始 JSON 展示。
- `PERM-REQ-12` 审批卡至少展示：
  - 工具名称或业务化工具标签；
  - Host 提供的本地化原因或审计原因；
  - 本次请求的目标权限范围；
  - “拒绝”和“允许一次”；
  - 请求剩余时间（存在时）。
- `PERM-REQ-13` 默认不提供“始终允许”。工具升权只有一次性许可；长期权限必须
  通过权限预设显式切换并重新确认。
- `PERM-REQ-14` 审批卡通过工具名、目标权限、具体原因和剩余时间表达本次
  操作边界，不再额外显示单次授权说明行，也不能把“允许一次”做成视觉上
  等价于“切换完全权限”。
- `PERM-REQ-15` 一个 interaction 只能提交一个结果；提交后禁用按钮并防止双击、
  键盘重复和重复网络请求。
- `PERM-REQ-16` 请求过期、服务器断线、页面重建、迟到响应和 interaction 已被
  撤回时一律失败关闭，不把未确认状态显示成已允许。
- `PERM-REQ-17` 拒绝、取消和不可用分别显示为不同结果；“不可用”不能伪装成
  用户主动拒绝。
- `PERM-REQ-18` 审批卡出现时，composer 和会话内容仍可保持上下文可见；审批
  需要遮挡或接管输入时，必须保留清晰的退出和返回路径。

### 新会话默认值

- `PERM-REQ-19` 只有 Host 暴露可写 `permission` 设置命名空间时，DSH 设置页才
  显示“新会话默认权限”。
- `PERM-REQ-20` 默认值选项来自 Host enum，不手写第二套目录；`custom` 和
  `auto` 不作为默认值。
- `PERM-REQ-21` 默认值使用 revision/CAS 写入，冲突时刷新并保留用户可见的本地
  选择，不自动重放写入。
- `PERM-REQ-22` 设置文案必须明确“只影响新会话”，不使当前会话看起来被改写。

### UI 与交互

- `PERM-REQ-23` 当前会话权限入口只显示一个业务 SVG，不显示文字、箭头或固定
  胶囊背景；使用 32vp 圆形命中区，仅在按压时显示圆形高光。入口位于 composer
  底部工具栏，窄屏下不得挤压附件和发送按钮。
- `PERM-REQ-24` 权限菜单使用紧凑菜单行；当前项使用勾选、文字和色值共同表达；
  完全权限和实验项使用明确的风险标记。
- `PERM-REQ-25` 审批卡沿用现有 `NativeInteraction` 的紧凑卡片语言：
  warning 状态条、工具 badge、可滚动详情、底部双操作。
- `PERM-REQ-26` 审批卡、权限菜单和完全权限确认在亮暗主题下都必须可读；暗色
  作为视觉验收默认主题。
- `PERM-REQ-27` 动效使用现有 `micro`、`overlay`、`surface` 和 `navigation`
  语义；减少动效时直接到最终状态，不使用循环装饰动画。
- `PERM-REQ-28` 移动端不复制 Web 的 Enter/Esc 键盘说明；存在硬件键盘时可在
  后续增加可选快捷键，但按钮和触控路径必须完整可用。
- `PERM-REQ-29` composer 底部工具行使用 2vp 控件间距；图片、文件、停止与
  发送控件使用 32vp 圆形视觉和命中尺寸，避免权限入口改变后行高回弹。

## 现有实现事实

- [NativeInteraction.ets](../../harmony/entry/src/main/ets/components/NativeInteraction.ets)
  已存在审批卡，显示“等待审批”、工具名、原因、拒绝和“允许一次”。
- [native-harness.mjs](../../gateway/src/native-harness.mjs) 已维护
  `approval/request` pending interaction，并把
  `allowed-once` / `rejected` 回写到 Host event result。
- [NativeHarnessClient.ets](../../harmony/entry/src/main/ets/services/NativeHarnessClient.ets)
  已有 `/pocket/api/native/answer` 通道。
- 目前仍缺少当前会话权限目录、`permissions` projection 透传、
  `/permission <preset>` 受控调用和新会话默认权限设置。

因此后续工作不是从零实现审批卡，而是补齐权限预设、权威状态和审批卡周围的状态
边界。

## 非目标

- 本轮不修改 `module.json5`，不申请任何系统权限。
- 本轮不实现本机应用锁、PIN、指纹或人脸。
- 本轮不实现多人账户、管理员/成员角色或资源级 RBAC。
- 本轮不实现 `allow-always`、持久升权规则或授权存储。
- 本轮不把 `auto` 变成新会话默认值。
- 本轮不把“允许一次”描述成永久的完全访问。
