# 界面设计系统统一需求

日期：2026-11-01

## 目标

全面审查 DSH Harmony 的原生界面元素，建立一份可执行、可测试、可持续维护的
视觉与动效事实源。所有界面应延续 DeepSeek Harness 的紧凑信息密度和业务语义，
同时在手机触控、安全区、键盘、主题、减少动效和减少透明度条件下保持一致。

## 范围

- 启动、引导、登录、恢复连接与错误页。
- 聊天正文、用户消息、附件、代码、Markdown、表格和 Diff。
- 会话标题区、抽屉、会话列表、工作区分区、搜索和置顶折叠。
- 任务计划 Dock、运行状态、回到底部、排队消息和待确认交互。
- 输入框、模型与推理气泡、附件操作和发送控制。
- 设置根页、全部二级页、关于页和兼容模式内嵌设置入口。
- 文件浏览器、文件预览、代码/Markdown/HTML/PDF/图片视图和灯箱。
- 菜单、弹层、加载、空状态、错误、Toast、对话框和桌面卡片。

## 必须满足

1. 视觉令牌由单一源码事实源提供，不在业务组件中新增同类颜色、圆角、行高或
   动效时长常量。
2. Base、Raised、Overlay、Field、Selection、Divider 等语义在浅色和深色下有
   明确映射；所有 SVG 图标随主题重新着色。
3. 页面标题、分组标题、正文、说明和微文案形成稳定层级。设置页不再使用比
   聊天主界面更大的独立排版体系。
4. 高频列表行保持紧凑；图标视觉容器可为 36vp，交互热区不小于 44vp。
5. 主操作、焦点和选中使用 DeepSeek 蓝；黄只表示等待，红只表示错误或危险。
6. 加载、空状态和错误使用同一套状态行语言；错误提供明确恢复动作。
7. 设置、抽屉、预览、文件层级、菜单和展开内容使用同一套方向、时长和曲线。
8. 减少动效时直接到终态；减少透明度时使用清晰实色表面。
9. API 23 的功能和层级不依赖 API 26 材质。
10. 文档必须包含设计令牌、组件配方、动效策略、例外和真机验收矩阵，并由
    `AGENTS.md` 索引。

## 非目标

- 不改变 Host 业务状态、协议、缓存和认证行为。
- 不覆盖或重写兼容模式中的上游 DSH 页面样式。
- 不把所有控件强行做成同一尺寸；尺寸按语义分组，表达密度和优先级。
- 不为装饰增加持续动画、粒子、呼吸光效或无因果关系的大面积模糊。

## 完成标准

- 设计、研究和实现规格落盘。
- 语义视觉令牌和共享图标按钮进入源码。
- 高频界面完成迁移，旧组件触达时有明确迁移规则。
- 自动化检查验证令牌、主题映射、热区和关键组件引用。
- `default` 与 `store` Release 构建通过。
- 真机结果在 E2E 表中有证据后才标记通过。
